# cloudflare-google-ip-list

Cloudflare Worker that keeps an account-level Cloudflare IP list (default name `google`) in sync with Google's published IP ranges. It has no HTTP handler: all it does is a `scheduled` handler on a cron (`0 */6 * * *`). See [README.md](README.md) for user-facing docs.

STOP. Your knowledge of Cloudflare Workers APIs and limits may be outdated. Always retrieve current documentation before changing Workers, KV, or Cloudflare API (Lists / bulk operations) code.

- Workers: <https://developers.cloudflare.com/workers/>
- Workers limits (subrequests, CPU, duration): <https://developers.cloudflare.com/workers/platform/limits/>
- KV: <https://developers.cloudflare.com/kv/>
- Lists API: <https://developers.cloudflare.com/api/resources/rules/subresources/lists/>
- Lists limits per plan: <https://developers.cloudflare.com/waf/tools/lists/#availability>
- MCP: `https://docs.mcp.cloudflare.com/mcp`

### Triggering a sync locally

```sh
npx wrangler dev --test-scheduled
curl "http://localhost:8787/__scheduled"
```

This hits the **real** Cloudflare account configured by `.dev.vars` and replaces the list's items. KV state stays local (`.wrangler/`).

## How the sync works

1. Fetch `GOOGLE_IP_RANGES_URL`, collect `ipv4Prefix`/`ipv6Prefix`, sort.
2. Resolve the account (`ACCOUNT_ID` var, or the single account the token can see).
3. Find the list by `IP_LIST_NAME`, creating it if missing.
4. Skip if the SHA-256 of the CIDRs matches KV key `<IP_LIST_NAME>:cidr-hash` **and** `num_items` matches.
5. Otherwise `PUT` all items (async bulk op), poll `bulk_operations/<id>` with exponential backoff, then store the new hash.

## Conventions and gotchas

- **Subrequest budget:** one run makes roughly 5 API/fetch calls plus up to `BULK_POLL_MAX_ATTEMPTS` (25) polls. Keep the total under the Workers subrequest limit for the Free plan (check the current value on the limits page) when adding API calls or changing the poll constants.
- All Cloudflare API calls go through `cfApi<T>(env, path, action, init)`, which throws `Failed to <action>: HTTP <status>, <errors>`. The README troubleshooting table relies on these messages, so update it if you change them.
- Structured logs are objects with an `event` field (`sync.start`, `sync.skipped`, `sync.complete`, `sync.failed`) and are documented in the README. Keep the two in sync.
- The worker owns the list and replaces every item on update. Never merge or append.
- `ACCOUNT_ID` is a var, not a secret (empty means auto-detect). The only secret is `CLOUDFLARE_API_TOKEN` (needs **Account Filter Lists: Edit**).
- `STATE` KV has no `id` in `wrangler.jsonc` on purpose. Wrangler provisions it on the first deploy, and the Deploy-to-Cloudflare button depends on this.
- Style: tabs, single quotes, semicolons, 140-char lines (Prettier). oxlint forbids `any`, non-null assertions (`!`), and brace-less `if`s, and requires `import type` for type-only imports.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `ci:`, `chore:`, `refactor:`, `style:`). release-please uses them to bump versions and write `CHANGELOG.md`, so don't edit the changelog or `version` by hand.
- Update `README.md` when behaviour, config, events, or errors change.

## Local Explorer (debugging)

While `wrangler dev` is running, relative to the dev server URL:

| Endpoint                                                     | Description                                                                      |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `GET /cdn-cgi/local/explorer/api/local/workers`              | List local Workers and their bindings                                            |
| `GET /cdn-cgi/local/explorer/api/storage/kv/namespaces`      | List KV namespaces (inspect the stored `cidr-hash`)                              |
| `POST /cdn-cgi/local/explorer/api/local/observability/query` | Read-only SQL (`SELECT`/`WITH`) over `spans` and `logs` (use `json(attributes)`) |
| `POST /cdn-cgi/local/explorer/api/local/observability/clear` | Clear captured traces and logs                                                   |

Example: `curl -X POST <base>/cdn-cgi/local/explorer/api/local/observability/query -H 'Content-Type: application/json' -d '{"sql":"SELECT service, name, outcome, duration_ms FROM spans WHERE parent_id IS NULL LIMIT 20"}'`

Full OpenAPI schema (large, last resort): `GET /cdn-cgi/local/explorer/api`
